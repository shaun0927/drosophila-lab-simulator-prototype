# 5-Minute Experience QA Pass

## Why this was added

Junghwan clarified that selection is not enough: each idea should be judged by imagining the actual 5-minute play experience, identifying problems, and iterating.

So every one of the 200 ideas now has:

- a 0:00-5:00 experience outline
- six timed beats
- design goal per beat
- QA rubric
- cut condition
- bespoke requirement for Tier 2 prototype

## 5-minute structure added to each idea

1. **0:00-0:30 Hook**
   - What the player sees immediately
   - What makes the situation strange

2. **0:30-1:30 First meaningful choice**
   - safe / expressive / risky
   - should express strategy or identity

3. **1:30-2:30 Visible consequence**
   - must not be only number changes
   - needs visual/log/reviewer/paper feedback

4. **2:30-3:45 Second pressure**
   - Reviewer, PI, ethics, rival lab, deadline, or Codex pressure

5. **3:45-4:40 Commit / push-your-luck**
   - submit, hide, publish, repeat, escalate, or retreat

6. **4:40-5:00 Result and replay hook**
   - screenshot-worthy result or reason to retry

## QA gates

Each candidate is now evaluated by:

- Is the first 30 seconds clear?
- Does the first choice have tension?
- Is feedback more than numbers?
- Is there a replay reason?
- Does it hit its cut condition?
- What bespoke UI/feedback would Tier 2 require?

## How to use this

Open any idea page. It now shows the imagined 5-minute play experience before the generic runner choices. Use that to decide whether the idea deserves deeper prototyping.

If an idea has a good title but fails the 5-minute flow, cut it or redesign it before implementation.
